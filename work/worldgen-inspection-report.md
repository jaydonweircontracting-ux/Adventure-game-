# World Generation & Related Systems — Inspection Report

**Date:** 2026-09-30 (BUILD 366) · **Read-only inspection** — no code changed.
**Purpose:** Prepare the design of a hierarchical landscape generator (WORLD → REGION → CHUNK → terrain → objects) on top of the existing architecture.

---

## 1. `src/game/worldCore.ts` — seed, clock, determinism primitives

- **World seed:** `DEFAULT_WORLD_SEED = 847291583` (hardcoded constant). `WORLD_SCHEMA_VERSION = 2`.
- **Coordinate system:** worldCore owns *time only* — no chunk geometry lives here. Chunk/field coordinates are defined in `src/App.tsx` and `src/game/elevation.ts`.
- **RNG:** `SeededRng` (add-constant `0x6D2B79F5` + imul-mix hash), serializable via `getState()/setState()`. Module rule: "Never use Math.random for world data" — mostly honored, with two violations found in this inspection (see §13).
- **Save/seed coupling:** `WorldCore.loadState()` throws if the save's seed ≠ the core's seed. The world is effectively **fixed-seed**: changing the seed invalidates every save. A landscape generator must keep this contract (or version the migration).
- **Clock:** 10 min/tick, 24h day, 30-day months, seasons from day-of-year. NPC sim advances on this clock (120 ms ticks in practice).

## 2. `src/game/worldMap.ts` — world map, biomes, climate (THE terrain source of truth)

**Single source of truth for terrain:** `generateWorldMap(seed, bounds)` → `GeneratedWorldTile[]`, computed **once at module load** in App.tsx (`generatedWorldTileByKey: Map<'x,y', tile>`). Everything downstream (`mapTileFor`, `chunkTerrain`, `regionStyleFor`, elevation base) reads from this frozen table.

- **Bounds:** `WORLD_MAP_BOUNDS` = x −10..20, y −8..22 (31×31). Frozen bit-identical core: `CORE_WORLD_BOUNDS` x 0..10, y 2..12 (generated by the legacy WFC `generateCoreWorldMap`). Outer ring and the far-eastern second continent (`SECOND_CONTINENT_BOUNDS` x 117..196, y −28..51, seed `seed ^ 0x5bd1e995`) are purely additive; the 96-tile ocean gap (x 21..116) is water-only filler.
- **Chunk coordinate unit:** each world-map tile **is** one gameplay chunk. No separate region layer exists yet — the "region" concept in the master prompt must be built new, but biomes already cluster: 3-octave fBm value noise (`makeSeededNoise`) at low sampling frequencies (≈0.26–0.3 per tile) for elevation/temperature/moisture, plus climate→biome weights (`climateBiomeWeights`), WFC adjacency constraints (`ALLOWED_NEIGHBORS`), and 3 passes of cellular-automata smoothing.
- **Biomes:** `'ocean' | 'shore' | 'meadow' | 'forest' | 'desert' | 'tundra' | 'rock'`. No per-biome hard squares — transitions are noise-driven.
- **Data per tile:** `{ x, y, row, column, biome, detail, nearBiomeBorder, climate: { elevation, temperature, moisture }, elevationLevel: 0–5 }`. `elevationLevelFor()`: 0 = ocean, then thresholds at 0.45/0.55/0.65/0.75.
- **Determinism:** fully deterministic — per-seed noise tables (`seed ^ 0x9e3779b9` etc. per field), per-tile `MapRng` for detail, WFC row-major with a single seeded RNG. Same seed ⇒ bit-identical core (guaranteed by comment and by `generateOuterTiles` seeding frozen core edge biomes first). Water/rivers: `detailFor()` only emits 'waves' on ocean; **rivers/lakes are not generated** — `MapTile.waterFeature` in App.tsx is only ever `'sea' | null` despite the type allowing `'river'|'lake'`. Water-drainage logic (master-prompt §7) is a gap.

## 3. `src/game/organicTowns.ts` — town anchoring

- **Town positions are authoritative in `src/game/landmarks.ts`** (`LANDMARKS: Record<'x,y', {name, kind}>` — 25 named sites; called "the single source of truth for named places"). `mapTileFor()` attaches `landmark` per chunk.
- **House layout:** `organicTownSpecs(variantSeed, variant, road, fieldSize)` — pure function, rects authored in 0..100 space scaled by `FIELD_SIZE/100`. Variant 1 = town (10–13 houses), 2 = village (8–11), 3 = hamlet (6–9, wider spacing). Houses cluster along road arms, 9-unit road-corridor exclusion + 2-unit overlap exclusion; **houses never sit on roads** (unit-tested per header comment).
- **Determinism:** LCG `s = (s*1664525 + 1013904223)` seeded from `Math.abs(variantSeed)*2654435761 + 987654321`; caller passes `variantSeed = chunk.x*31 + chunk.y*17`.
- **Town influence:** the master prompt's TOWN → FARMS → PASTURES → WOODLAND → WILDERNESS gradient is only partially present: forest clusters ring non-starting towns (3×4–6 trees, BUILD 342) and farms scatter in ~40% of meadow chunks (`fieldFarmRects`, same LCG family), but there is **no town-influence field / mask** — towns don't flatten elevation, clear vegetation noise, or spawn satellite structures (fences, fields, wood piles). `fieldFarmRects` uses `Math.sin(seed)*10000` hash RNG (different family from SeededRng, but deterministic).
- **Starting area** (`isStartingArea`: chunks 3–5 × 6–8, center 4,7) is hand-authored: hardcoded house rects from the user's mover screenshots, flattened elevation, sparse perimeter trees.

## 4. `src/game/groundDetail.ts` — per-chunk ground rendering (BUILD 339+341+355+366)

- `renderGroundDetail(spec: GroundDetailSpec): HTMLCanvasElement` — paints a **280-unit chunk to a static 1120×1120 canvas (4 px/unit)**. Called with `{ terrain, field, path, road, roadRect, sea, seed, paints?, hills? }`.
- **Determinism:** `mulberry32(spec.seed)` where `seed = (chunk.x*73856093 ^ chunk.y*19349663) >>> 0`. No Date/Math.random. "Painted once per chunk and cached by the caller." Dither via `createPattern` (two fill calls, not 300k rects) — performance-conscious.
- **Content:** per-biome dither/tufts/flowers/cracks/pebbles; dirt roads with ragged fringe + wheel ruts (arm strings drawn from `spec.road`, fraction rects `x:0.47, w:0.09`); map-builder `paints[]` override base AND roads; **BUILD 355** sub-chunk elevation tint + CraftPix cliff faces drawn on cliff steps; **BUILD 366** biome decorations (forest mushrooms, shore shells, desert cacti).
- **Seam note:** all detail is **per-chunk local random** — tufts/roads/dirt patches do not cross chunk borders. Road arms do reach edges (arms extend to 0/SIZE), so roads are visually continuous; everything else stops at the border. The generator in the master prompt must replace `ri(SIZE)` scatters with world-coordinate-sampled noise to kill this seam.

## 5. Road generation — hardcoded, not generated

- **Roads are NOT procedurally generated.** `worldRoadAt(x, y)` (App.tsx:325) is a set of **hardcoded coordinate ranges** (main roads y=7 x −1..9, x=4 y 4..12, etc. + a second-continent web). `mapTileFor()` derives the per-chunk piece by neighbor checks: `'n'` arm iff `worldRoadAt(x, y-1)`, etc. — **border-continuous by construction** (each side of a chunk edge consults the same global predicate), no phantom stubs.
- **Three mutually inconsistent road-corridor definitions** (all stale in at least one place):
  - Visual ground road: fraction `x:0.47, w:0.09` → **131.6–156.8** field units (App.tsx:5585, 8858).
  - Tree exclusion `pointOnFieldRoad()` (App.tsx:592): `y/x ∈ 44..59` — **old 0..100-space corridor, never rescaled** to 280-unit fields. Trees are NOT excluded from the real road band; they are excluded from a phantom 44–59 corridor. Likely a live bug (trees can spawn on roads).
  - NPC A* road preference `ROAD_MIN=64, ROAD_MAX=80, ROAD_MID=72` (npcNavigation.ts:132) — derived from the **old 140-unit field** (comment cites "--road-x 47% on the 140-unit field"); real band center is 144.2. NPC road-following bonus misses the road.
  - BUILD 355 `fieldRoadCorridors()` (App.tsx:274): `0.47*280=131.6, w=0.09*280=25.2` → **131.6–156.8** (agrees with visuals; used by elevation flattening + cliff collision exemption).
- **Recommendation for the generator:** define ONE canonical `roadCorridorsFor(chunk)` (the BUILD 355 version is closest) and make trees, A*, and NPC sim consume it. Caravan routes (`civilization.ts`) use road-junction waypoints that reference field positions like `{x:70,y:70}` at chunk 4,12 — also 140-space stale; audit before touching.
- Roads as gameplay objects: `hiddenRoadChunks` (editor can hide roads per chunk), bridges (`bridge = ocean && road !== 'none'`), roads exempt from cliff collision and elevation flattening. No POI/travel metadata beyond `isOnFieldRoad`.

## 6. Terrain/tile definitions

- `mapTileFor(point: Point): MapTile` (App.tsx:374, exported for iso) is the per-chunk tile authority: `{ x, y, terrain, worldBiome, regionStyle, waterFeature, waterEdge, road, bridge, landmark, elevationLevel }`.
- `Terrain` ∈ meadow/forest/rock/shore/desert/tundra/ocean; `fieldPalettes: Record<Terrain, {field, path, glow}>` (App.tsx:188, exported) drives both 2D and iso ground colors.
- `FieldTree` (exported): `{ id, x, y, scale, variant, style: RegionStyle, sprite: EnvSpriteKey, flip }` — **field units 0..280** since BUILD 354 (renderer and `fieldTreeBaseRect` agree; the old non-starting-chunk render misalignment is resolved by using true field units everywhere).
- Tree placement (App.tsx:591): per-chunk `Math.sin(seed++)` hash RNG, 8–12 trees, `shouldPlaceVegetation(worldX, worldY, 0.42)` noise gate (world-anchored Perlin — **border-consistent by construction**), 9-unit tree separation, exclusion vs houses/roads/start. Species from `envSpriteForTerrain(terrain, variant)` (FreeEnvironment pack sprite atlas boxes in `ENV_SPRITE_BOXES`).

## 7. Collision & walkability

- **Unit of collision:** field units on the active chunk; `isFieldPositionBlocked(position, chunk, houseOffsets)` (App.tsx:726): water (`pointInWater` — only full-chunk sea, `waterFeature==='sea'`) → tree base rects (`fieldTreeBaseRect`: narrow trunk box ~4.2×2.8 units, canopy passable) → tavern annexes → carriage stations → editor solids → building rects (0.35 padding) → farmhouses. Trees honor editor deletions (`felledTreeKeys`, `editorDeletedTreeKeys`).
- **Movement pipeline:** `resolveFieldMovement` (App.tsx:843) tries full / x-only / y-only slides, wraps chunks (`wrapFieldPosition` — blocks entry into non-generated or ocean chunks), then applies **BUILD 355 cliff blocking** (`cliffBlocksMove`): walking *up* a cliff step (`isCliffStep`: |Δlevel| ≥ 1 with high side ≥ 3) is blocked; walking down is always allowed so the player can't be trapped; road corridors exempt.
- **No per-tile walkability table exists** — walkability is resolved by probing object rects, not a tile grid. The master prompt's `walkable/height/slope/movementCost` per tile is a new concept; the cliff system provides only the height rule. Note NPC sim does NOT apply cliff blocking (player-only) — see §8.

## 8. NPC navigation

- **Two separate pathfinders:**
  - `src/game/npcNavigation.ts` `findPath(from, to, obstacles, viaDoor?, roadPiece?): NavPoint[] | null` — **positional args**, coarse A* on a **35×35 grid of 4-unit cells** (covers 140×140) with building-rect blocking, no diagonal corner-cutting, 4000-node guard, road-cost preference (`OFFROAD_COST = 2.0`), linear-scan open list. **Stale for 280-unit fields**: `toCell` clamps to cell 34, so any destination in the lower/right 140 units collapses to the grid edge — NPC pathfinding is effectively quarter-chunk. This must be fixed (grid 70×70 or dynamic) before NPCs can use a richer landscape.
  - `src/game/iso/projection.ts` `findPath({...})` — **object-based**, tile-space; used only by the iso demo rooms (`IsoRoom.tsx`, `IsoInteriorView.tsx`), not the live sim.
- **Townsfolk pipeline** (`src/game/townsfolk.ts`): `advanceOne(npc, anchors, clock, nav, step, resolveTarget)` — schedule (`townsfolkTarget` or BUILD 366 `villageTarget` override) picks WHAT (activity, target, indoors flag); `TownsfolkNavContext { housing, doors: DoorwayLink[], obstacles, roadPiece? }` drives HOW: location machine OUTDOOR → ENTERING → INTERIOR → EXITING → SLEEPING, doorways crossed on foot, `indoorRestSpot` / `interiorWanderSpot` for indoor targets, stuck detection (`STUCK_TICK_LIMIT=60`, `MAX_REPLANS=1`). Crowd separation via `separateCrowd`. **NPCs never apply `cliffBlocksMove`** — in hill chunks they will walk straight up cliff faces (visual/logic seam; collision probe is player-side only).
- Mosslight has 12 authored NPCs with homes/beds (`mosslightObstacles()`, `buildMosslightHousing()`); anchors are hand-authored (`TownsfolkAnchors`), not landscape-derived. The master prompt's job-sites (mines/farms/forests as NPC destinations) don't exist yet.

## 9. Rendering — 2D field

- **DOM-based field:** absolutely positioned divs with `%` coordinates (`fieldPct(v) = v/280*100%`). Layers: `FieldGroundLayer` (the 1120px groundDetail canvas, inside the camera-transformed `.field-world-layer` since BUILD 340) → road overlays → buildings → trees (ENV sprite divs with `flip` via negative scaleX since BUILD 366) → NPCs/player.
- Camera: zoom 2.25 default, `screen = zoom*layer + (0.5 − zoom*playerFrac)*size`, clamped at chunk edges (BUILD 350/351); BUILD 346 neighbor-chunk rendering at zoom < 100%.
- `IsoFieldView` is a pure canvas renderer (see §10); a "🏔️ 2.5D Field" options toggle (`ag-iso-field-beta`) swaps presentation without touching sim/HUD/persistence.

## 10. `src/game/iso/IsoFieldView.tsx` — iso consumption

- Imports from `../../App`: `buildingDoorwaysFor, fieldTreesFor, mapTileFor, fieldPalettes, FIELD_SIZE` (+ types `Point`). **Circular dependency App ↔ IsoFieldView exists** (flagged in BUILD 366 notes — should be extracted).
- Builds a `scene` memo per chunk: `buildingDoorwaysFor(chunk)` → iso boxes with pitched roofs + door markers at real doorway positions; `fieldTreesFor(chunk)` → stylized canvas trees; `mapTileFor(chunk).terrain` → `fieldPalettes` ground color, road band via `isRoadTile` (tile-space, ROAD_HALF=5 tiles ≈ correct for the 0.47/0.09 band).
- **BUILD 366 detail:** per-tile deterministic hash `((tx*73856093) ^ (ty*19349663) ^ terrain.length*83492791)` → tufts/mushrooms/shells/pebbles/flowers drawn per visible tile (culled to viewport, viewport-culled floor).
- Renders only: buildings, trees, townsfolk (live `Townsperson[]` as LPC sprites), player. **Does NOT render**: creatures, drops, travelers, fake adventurers, editor-placed objects, POIs, elevation/cliffs (flat iso ground — cliff system is 2D-only for now). Tap-to-move + tap-to-talk wired in BUILD 366.

## 11. Existing elevation (BUILD 355)

- `src/game/elevation.ts`: `cellLevelAt(ctx, wx, wy)` — 0–5 quantized levels on a **20-unit cell grid** (`ELEV_CELL=20`, 14×14 cells/chunk), sampled at cell centers from **absolute world coordinates** (`hillValueAt(wx,wy)`: Perlin fBm broad 1/140 + detail 1/46, amplitude 1.65 in hill country / 0.55 in lowlands, centered on the chunk's `elevationLevel`). Because it samples world coords, **chunk borders agree by construction** (plus a 1-cell halo in `buildGroundHills`).
- `ElevContext` (implemented in App.tsx:297): `baseLevelAt` ← `mapTileFor().elevationLevel`; `isFlatChunk` ← starting area / landmark / sea chunks (flattened); `isRoadAt` ← `fieldRoadCorridors`.
- **Cliff blocking:** `cliffBlocksMove(ctx, wx0, wy0, wx1, wy1)` — uphill cliff steps blocked, downhill free, roads exempt. Wired into player movement only (`resolveFieldMovement`). Rendering: `buildGroundHills` → `GroundHills { count, levels, base, cliffKind }` → groundDetail paints CraftPix kit cliff slices (`kitAssets.ts`: `getKitTileset`, `kitCliffSlice`, `kitCliffLip`) on the lower cell of each cliff step + plateau tint.
- Gaps vs the master prompt: no valleys/water interplay (rivers don't exist), no POI/elevation interaction, NPC sim ignores cliffs, iso renderer ignores elevation.

## 12. Save / persistence

- **Save file:** `SAVE_FILE_FORMAT='adventure-game-save'`, v2, validated by `migrateSave` (src/game/persistence.ts). Stores player, inventory, quests, clock, townsfolk (`serializeTownsfolk`/`restoreTownsfolk` — incl. memories, gold, relationships), etc. **Chunk terrain is never persisted** — it is regenerated deterministically from seed on every load. This is the right foundation: a landscape generator only needs to stay deterministic; saves stay valid as long as `mapTileFor` output for existing chunks is unchanged.
- **Editor overrides (localStorage, applied on top of generated terrain):** `worldEditorObjects` (placed houses/trees/rocks → `editorSolids`), `worldEditorFlags`, `worldEditorDeletedTrees`, `worldEditorDeletedCorn`, `worldEditorHiddenRoads`, `mapBuilderPaints` (per-chunk painted tiles → override groundDetail base+roads, `mapBuilderSolidsFor`), `worldEditorXMarks` (persistent ❌ markers), `editorChangeLog` (300-entry audit log).
- **Danger:** the generator must apply editor overrides AFTER procedural placement (current order already does), and any change to `fieldTreesFor` tree `id` assignment would orphan `worldEditorDeletedTrees` ids.

## 13. Determinism audit — seeds in use

| System | Seed source | RNG | Verdict |
|---|---|---|---|
| World map core | `DEFAULT_WORLD_SEED` | MapRng / fBm hash | Deterministic, frozen |
| World map outer ring / 2nd continent | seed ^ consts | MapRng, per-tile hash | Deterministic, order-independent |
| Elevation | fixed Perlin seeds `0xE1E7A710`/`0x0E177A1` + world coords | Perlin | Deterministic, world-anchored |
| Trees / accents / farms / towns | chunk-derived (`92837111` family) | `Math.sin(seed++)*10000` hash | Deterministic but fragile (id-order-dependent, not a stream) |
| POIs (`poisForChunk`) | `chunkSeedNumber(x,y,worldSeed)` | `SeededRng` | Deterministic; **positions in 0..124 space** (140-unit field remnant) while fields are 280 — POIs cluster in the top-left. Flag. |
| Ground detail canvas | `(cx*73856093 ^ cy*19349663)` | mulberry32 | Deterministic per chunk, but chunk-local (border seam by design) |
| Rumors (`talkToNpc`) | — | **`Math.random()`** | Non-deterministic; violates module rule (App.tsx ~line 5600) |
| `fieldFarmRects` | chunk hash | `Math.sin` hash | Deterministic |

**Math.sin-based hash RNGs** (App.tsx trees/accents/farms, organicTowns LCG) are deterministic but not seekable/stable across engine edits — a `mulberry32`-or-`SeededRng` stream keyed by `(worldSeed, chunkX, chunkY, subsystem)` (per master-prompt §35) is the safer substrate for the new generator.

## 14. Known seams / discontinuities between chunks (design must address)

1. **Ground-detail scatter stops at borders** (§4) — every chunk's tufts/dirt/pebbles are chunk-local random. Fix: sample world-anchored noise in `renderGroundDetail`.
2. **Tree noise is world-anchored** (`shouldPlaceVegetation`) but the **acceptance RNG is chunk-local** (`Math.sin(seed++)` sequence with rejection sampling) — the same tree id can appear/disappear based on intra-chunk RNG order; density is continuous but exact placements aren't neighbor-aware. Cluster masks (master-prompt §§16–17) need cross-border cluster seeds.
3. **Three stale road-corridor definitions** (§5): trees use 44–59 (wrong), NPC A* uses 64–80 (140-space), only BUILD 355's 131.6–156.8 matches visuals. Also NPC road bonus currently misses the road.
4. **NPC A* grid covers 140×140 of a 280 field** (§8) — quarter-chunk pathfinding.
5. **POI positions authored in 0..124/140 space** — cluster top-left of 280 fields.
6. **No rivers** — `waterFeature` is sea-only; `mapTileFor` types promise river/lake.
7. **NPCs ignore cliffs**; iso renderer ignores elevation.
8. **No town-influence field** — farms/forest rings are special-cased, not gradient masks.
9. Elevation base (`elevationLevel`) is per-chunk flat from world-map climate — sub-chunk relief exists but there is **no regional landform layer** (no ridgelines/valleys spanning chunks); the master prompt's MACRO layer is the missing piece, and `climateFor`'s noise already spans regions — expose it as the macro substrate.

## 15. Recommendations for the generator design

- **Keep the source-of-truth chain:** `generateWorldMap` table → `mapTileFor` → everything else. Add a **region layer** computed from the existing climate noise (it already spans multiple tiles): derive `regionId` + macro landform (range/valley/basin) per chunk, neighbor-aware, cached.
- **World-anchored sampling everywhere:** elevation.ts is the pattern to copy — pure functions of absolute world coords. New passes (moisture/forest/rock/POI density fields) should be fBm over world coords at macro/meso/micro frequencies, then quantized per chunk/cell.
- **Unify seeds:** one `subsystemSeed(worldSeed, cx, cy, 'trees'|'rocks'|...)` helper (SeededRng/mulberry32 streams), replacing the `Math.sin` hash chains and `Math.random()` rumor roll.
- **Single road-corridor module:** `roadCorridorsFor(chunk)` (BUILD 355's math) consumed by tree placement, NPC A*, caravan routing, and cliff exemption; fix POI 140-space and A* 35×35 grid as part of it.
- **Rivers:** derive from the elevation field (downhill tracing on the world-anchored cell grid); water tiles need real `waterFeature: 'river'`, collision, bridge-aware roads, and map-screen agreement.
- **NPC-facing metadata:** expose per-chunk activity sites (`{ kind: 'farm'|'mine'|'forest'|'water', rect, resources[] }`) — townsfolk schedules currently use hand-authored anchors only; this is the bridge to the AI-village work.
- **Preserve save compat:** never change `mapTileFor` output for existing chunks in ways that break tree-id/editor-deletion id mapping; version any change via `WORLD_SCHEMA_VERSION`.
